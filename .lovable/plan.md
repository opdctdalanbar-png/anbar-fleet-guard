# تحويل النظام إلى قاعدة بيانات مشتركة (Lovable Cloud)

## سبب المشكلة الحقيقي

لا يوجد حالياً أي خادم أو قاعدة بيانات في التطبيق. كل الحسابات والمولدات والتقارير محفوظة داخل متصفح الجهاز نفسه فقط. لذلك:

- الحساب المضاف من لوحة التطوير موجود في متصفحك أنت فقط.
- الرابط الحي (الموقع الرسمي) يُعد مكاناً مختلفاً للتخزين، فلا يرى ذلك الحساب.
- الفني الذي يفتح النظام من هاتفه لا يجد حسابه إطلاقاً.

المسألة ليست في مفاتيح سرية ولا في صلاحيات RLS، لأن هذه الأمور غير موجودة بعد. الحل هو إنشاء قاعدة بيانات حقيقية مشتركة.

## ما سيتغير للمستخدم

- الحسابات التي ينشئها المهندس تعمل فوراً من أي جهاز ومن الرابط الرسمي.
- المولدات والتقارير والصور تُحفظ مركزياً ويراها الجميع حسب صلاحيته.
- قائمة الفنيين تتحدث مباشرة بعد الإضافة أو التعديل أو الحذف.
- تسجيل الدخول يبقى باسم مستخدم وكلمة مرور كما هو الآن، وتبقى الحسابات الثلاثة الأساسية تعمل.
- البداية من الصفر: لا نقل لبيانات محلية سابقة.

## خطوات التنفيذ

1. تفعيل Lovable Cloud (قاعدة بيانات + حسابات + تخزين ملفات).
2. إنشاء الجداول: الملفات الشخصية للمستخدمين، أدوار المستخدمين (مهندس / مدقق / فني)، المولدات، التقارير اليومية.
3. ضبط صلاحيات الوصول:
   - المهندس: كامل الصلاحيات على المولدات والفنيين والتقارير.
   - المدقق: قراءة فقط لكل شيء.
   - الفني: يرى المولدات في موقعه، ويضيف/يعدّل تقريره اليومي فقط.
4. إنشاء الحسابات الثلاثة الأساسية ضمن الترحيل الأول بكلمات المرور نفسها.
5. تحويل شاشة الدخول وشاشات المهندس والمدقق والفني للقراءة والكتابة من قاعدة البيانات بدل التخزين المحلي.
6. إعادة جلب البيانات تلقائياً بعد كل عملية إضافة/تعديل/حذف، مع تحديث حي لقائمة الفنيين والمولدات.
7. نقل صور التقارير إلى تخزين الملفات بدل حفظها كنص داخل السجل.
8. النشر ثم اختبار إضافة فني جديد وتسجيل الدخول به من الرابط الحي.

## تفاصيل تقنية

- Supabase عبر Lovable Cloud؛ الدخول باسم مستخدم يُحوَّل داخلياً إلى بريد اصطناعي `<username>@opdc.local` مع Email/Password auth.
- جداول: `profiles`, `user_roles` (enum `app_role`) مع دالة `has_role` بنمط SECURITY DEFINER، `generators`, `reports` (فهرس فريد على `generator_id + date`).
- كل جدول جديد في `public` يحصل على `GRANT` صريح ثم `ENABLE ROW LEVEL SECURITY` ثم السياسات.
- إنشاء/تعديل/حذف حسابات الفنيين يتم عبر `createServerFn` يتحقق أولاً من دور المهندس ثم يستخدم Admin API لإنشاء المستخدم — لا مفاتيح سرية في كود المتصفح.
- القراءات في الواجهة عبر TanStack Query مع `invalidateQueries` بعد كل تعديل، إضافة إلى اشتراك Realtime على جدولي `profiles` و`generators`.
- الصور في bucket خاص `report-photos` مع سياسات حسب الدور.
- تُحذف طبقة `src/lib/genstore.ts` المعتمدة على LocalStorage بعد إتمام التحويل.
